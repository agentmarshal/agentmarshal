The core of the change is sound: the gate's transcript wording is preserved byte-for-byte through `finding_reviewer_identity_refusal` (the success path still passes the old fallback string to `check`), the commit prompt reassembles byte-identically from the extracted `_prose_instruction`/`_verdict_protocol` helpers, `_parse_verdict`'s commit-path behaviour is unchanged, artifact refs are protected from sentinel injection both by the `|` prefix and by `_reject_control_characters` at record-validation time, and every scenario in the published spec has a test whose docstring names it. Below are the findings.

**doc-runbook-keeps-human-path-inline** — `docs/sidecar.md:414` inserts `agentmarshal review --reviewed-finding` immediately above the pre-existing `agentmarshal submit-review --reviewed-finding` in the same copy-pasteable research-findings block, with nothing marking the two as alternatives. An adopter running the block in order records two review records for one finding, and `run_findings_gate` reads `reviews[-1]` — so the hand-recorded human verdict supersedes the automated one, leaving the human path looking mandatory. That is exactly the routing the 2026-09-18 contract amendment added `docs/sidecar.md` to scope in order to replace ("its findings-lane runbook routes a finding review to the human path, which this task replaces").

**absolute-artifact-ref-refused-by-snapshot-guard** — `review.py:744-750` computes `destination = snapshot / artifact.reference`; for an absolute reference pathlib discards `snapshot`, `destination.resolve().relative_to(resolved_snapshot)` raises `ValueError`, and the launch is refused with "finding artifact reference escapes the snapshot". The branch is marked `# pragma: no cover - guarded by resolver`, but `artifacts.artifact_path` explicitly supports absolute references (`if not candidate.is_absolute()`), and `_run_finding` in `cli.py:951-956` accepts any non-empty ref string. So a finding pinned with an absolute in-project path is verified by `run_findings_gate` but can never be reviewed by the launcher, and the branch that refuses it is both reachable and untested.

**extract-snapshot-unused-project-root** — `review.py:732-733`: `_extract_finding_snapshot` takes `project_root` and never reads it; confinement is computed from `snapshot.resolve()` alone. `test_finding_snapshot_uses_the_artifact_reference_not_its_resolved_path` passes `repo` to satisfy a parameter that has no effect.

**resolver-test-asserts-absent-name** — `tests/test_gate.py:249-256`: the test that is meant to demonstrate the resolver "exists once" (tasks.md 2.4, which names `_artifact_path`) asserts `not hasattr(gate_module, "actor_git_identities")` — a name that has never existed in `gate.py` (the helper is `_actor_git_identities`). The assertion is vacuously true and would not notice a re-added private copy of the resolver in `gate.py`.

**finding-summary-absent-from-prompt** — `review.py:815-824` builds the finding prompt from the contract and the verified artifact bytes but never includes the finding record's `summary`, which per ADR-0009 Decision 1 is the one-line claim the finding makes about those artifacts. The reviewer is asked to judge evidence without being shown the conclusion it was recorded to support.

**reviewed-contract-decision-unrecorded** — `review.py:876` records `reviewed_contract` for a finding review and `review.py:823` renders amendment history into the finding prompt. ADR-0011's "Left open" section states that "what the findings lane does with any of it is also unsettled". The change settles it, correctly and consistently with `openspec/specs/review-evidence/spec.md`, but `design.md` records neither the decision nor a departure, which acceptance criterion 1 asks for.

**scoped-task-not-refused-before-run** — `_launch_finding_review` checks latest-finding and reviewer independence before running the reviewer, but not the empty-scope admission rule. `run_findings_gate` refuses a task whose contract declares a scope, so launching a finding review on a scoped task spends a reviewer run and writes a permanent, append-only review record for evidence the lane will deny — the outcome design.md's decision "The two pre-run refusals are requirements" says the pre-run checks exist to prevent.
