**What holds up.** The commit prompt really is reconstructed byte-for-byte by the `_prose_instruction`/`_verdict_protocol` split; `_parse_verdict`'s subject-field generalization leaves the commit binding's refusals intact (a commit-path verdict carrying `reviewed_finding` still trips the unsupported-field check); `artifact_path` genuinely exists once and both callers hold the same function object; and the gate's identity check emits the same strings on both branches as the code it replaced, so the pinned transcript is safe.

Now the findings.

**REVIEWER-CONTRACT-DOC-STALE** — `docs/quickstart.md:46-91` is the operator-facing definition of `AGENTMARSHAL_REVIEWER_CMD`, and it still says the command "starts with its working directory set to a metadata-free snapshot of the reviewed commit" and that the verdict block requires `reviewed_commit`, with "any other key refused". After this change the same configured command is launched for a finding review into a snapshot of verified artifacts and must print `reviewed_finding`. `openspec/specs/reviewer-adapter/spec.md` makes that documentation a requirement, and neither it nor quickstart is amended. `docs/sidecar.md` was pulled into scope for exactly this reason — but sidecar is the placement-specific doc; an embedded-placement operator, whom the findings lane serves equally, gets no documentation of the new path and is actively told the wrong verdict field.

**CLOSED-TASK-NOT-REFUSED-BEFORE-RUN** — `src/agentmarshal/journal/review.py:780-811` implements three pre-run refusals (not-latest, non-independent reviewer, declared scope) but not the findings lane's first admission rule. ADR-0009 Decision 3 lists "the task is not closed" first among what the lane checks, and `run_findings_gate` (`gate.py:154-157`) refuses on it. Launch a finding review on a completed or abandoned task and `load_task_status` succeeds (state `done`), the reviewer run is spent, and `submit_review` appends a `review` record after the terminal record — no writer-side guard exists (`records.py:665-740` checks shape, task and finding binding, never lifecycle). From then on `project_status` raises "task has a lifecycle record after a terminal record" (`status.py:59`), so `load_task_status` fails permanently and `status`, `report`, `brief`, `gate` and `complete` all stop working for that task, in an append-only journal that cannot be corrected. The commit path shares this hole, but this change is what makes it reachable for findings, and the design's own rationale — "the admission rule is asked before the reviewer runs, not after" — names it.

**IDENTITY-SCENARIO-HALF-TESTED** (advisory) — `tests/test_review_launcher.py::test_finding_review_refuses_the_recorder_before_running` covers only the first half of the scenario "a reviewer who is not independent of the recorder is refused". The second half — "the recorder resolves to no git identity at all" — takes a different branch of `finding_reviewer_identity_refusal` (`gate.py:122-124`) returning different wording, and no launcher test reaches it.

**DEPARTURE-NOT-IN-DESIGN** (advisory) — design.md's decision says the launcher reuses "the gate's identity resolution **and refusal wording**". `finding_reviewer_identity_refusal(..., launching=True)` deliberately emits new wording instead, and the reason is recorded in the gate.py docstring rather than in design.md, which the first acceptance criterion requires.

**ABSOLUTE-REF-SNAPSHOT-PATH-MISMATCH** (advisory) — `review.py:723-728` derives `snapshot_reference` from the *resolved* path for an absolute reference while the prompt names the original absolute spelling (`review.py:262,275`). A reviewer that follows "Verified artifact: /repo/evidence/x.md" reads the live working-tree file rather than the pinned snapshot copy, which is the tree the design set out to keep it away from; the snapshot holds those bytes at `evidence/x.md` instead. `test_an_absolute_artifact_reference_records_a_review` checks only the record, not the path.
