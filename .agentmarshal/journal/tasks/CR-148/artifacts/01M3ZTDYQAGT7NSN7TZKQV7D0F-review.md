Прочитал контрактный материал (`openspec/specs/local-state/spec.md`, архив change-а, design.md), код `localstate.py` / `project.py` и тесты. ADR-сверка сходится: шесть имён (`log/`, `extensions/`, `deps/`, `trust.toml`, `switches.toml`, `plan.toml`) совпадают с картой ADR-0014 строки 159–164 и ADR-0022 §247; helper не скопирован, а переименован (`_git_common_dir` → `git_common_dir`, один вызывающий — `project.py:427`); `local_state` ничего не создаёт; никто в тулзе модуль ещё не использует (grep по `src/` даёт только сам `localstate.py`); все восемь сценариев delta-спеки названы в docstring-ах тестов. Полную CI-последовательность в этой песочнице запустить не удалось (нет `uv`, запуск `pytest` заблокирован правами) — статически тесты выглядят проходимыми, но независимо это не подтверждено.

**design-claims-init-refuses-indeterminate-git-answer** — в `openspec/changes/archive/2026-10-03-local-state-location/design.md` (раздел Decisions, абзац про `_git_common_dir`) записано: «before, an indeterminate comparison refused only when both calls failed (two `None`s comparing equal) and passed silently when one did; now any failure refuses with the cause named». Код этого не делает. В `src/agentmarshal/project.py:427` осталось то же сравнение `git_common_dir(git_root) == git_common_dir(resolved_host)`, а `reason` объявлен `field(compare=False)` (`project.py:346`), поэтому: при двух неопределённых ответах (`returncode != 0` с обеих сторон — например git старше 2.31, не понимающий `--path-format=absolute`, или stale `.git`-указатель) answers снова равны и init отказывает старым сообщением «is a worktree of host», то есть без названной причины; а при односторонней неопределённости (один `path=None`, другой — настоящий путь) объекты не равны и init молча продолжает — ровно тот случай, который design.md объявляет закрытым. Это архивный, то есть постоянный, документ безопасностного решения: он обещает защиту, которой в коде нет. Нужно либо отказывать с причиной на любом неопределённом ответе (использовать `reason`/`path is None` явно, а не через `==`), либо исправить формулировку в design.md и `tasks.md` 1.1.

**git-common-dir-error-contract-untested** — новый публичный контракт `git_common_dir` (`project.py:349-388`) обещает `GitNotAvailableError` при неработающем git и при не-UTF-8 выводе, но ни один тест этого не проверяет; соответственно и ветка `except GitNotAvailableError` в `src/agentmarshal/localstate.py:86-88`, которая превращает её в `LocalStateError` с именем репозитория, мертва в тестах — а это как раз путь, который acceptance требует «never a traceback». `tasks.md` 1.1 при этом считает пункт проверенным через «grep находит один helper» и чужой init-тест.

**outside-git-test-asserts-git-wording** — `tests/test_localstate.py:200` утверждает `"not a git repository" in message`, то есть зашивает англоязычную формулировку git, тогда как соседний тест (`test_a_stale_git_pointer_reports_gits_reason`, строки 205-245) в своём docstring прямо объясняет, почему слова git угадывать нельзя, и спрашивает их у самого git. При локализованном git (`LANG`) или переформулировке в новой версии первый тест упадёт по причине, не связанной с проверяемым поведением; это единственное место в `tests/` и `src/`, которое зависит от текста git.
