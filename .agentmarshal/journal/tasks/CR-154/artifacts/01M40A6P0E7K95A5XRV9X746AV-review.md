**Advisory findings.**

`untabled-write-only-refusal` — `src/agentmarshal/journal/records.py:714-719` puts the non-writable-type refusal inside `_validate_record` but outside `_RULES`/`_RULE_FROM_SCHEMA`, so `test_every_read_rule_has_its_schema` cannot see it, while the record-schema spec this change itself edits still names exactly one check that legitimately "holds no entry" — the schema-version precondition (`openspec/specs/record-schema/spec.md:62-66`). No requirement in the delta asks for this refusal either: "The record types are declared once" only requires the writable types be *derived from* the registry or pinned by test. It is dead code today (all nine types are writable, and ADR-0022 §3's third column is "admitted after a terminal record", not writability), so nothing changes behaviourally — but the capability's single-table invariant now has an unacknowledged second exception.

`fourth-validator-beyond-criterion` — acceptance criterion 4 enumerates three shared validators (character-bounded text, canonically-byte-bounded JSON, forgeable-text); `records.py:605-614` and `_RULE_FROM_SCHEMA` add a fourth, `bounded-text-bytes`. It is well-grounded — ADR-0022:159 bounds `excerpt` at 4 KiB, a byte measure a character count cannot express, and routing a string through `bounded-json` would charge it quote and escape bytes — and it is declared in the proposal, design.md and the delta spec. Flagging only so the operator sees that the criterion's list was widened rather than met literally.

`recorded-by-reorder-changes-message` — criterion 3 asks that `finding` move onto the flag "with no change in behaviour". The requirement moved from `_validate_finding_record` (the `finding` rule, 11th in `_RULES`) to `_validate_recorded_by` (the `recorded-by` rule, 20th), which puts it behind `provenance` (19th). A `finding` record that both omits its recorder and carries a missing or invalid `source` now reports `record field 'source' must be one of …` where it used to report `finding record requires a resolvable recorder …`. The refusal set is unchanged, the message string for the recorder case is byte-identical, and no test pins the old ordering (`tests/test_findings.py:322` and `tests/test_attestation.py:193` both supply a valid `source`); design.md states the reorder explicitly. Worth naming because it is the one place the literal "no change in behaviour" does not hold.
