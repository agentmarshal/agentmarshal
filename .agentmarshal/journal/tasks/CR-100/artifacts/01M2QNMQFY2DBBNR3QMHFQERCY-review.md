Проверил: реализация, спеки, ADR-0005/0008 и тесты. Блокирующих дефектов не нашёл — ниже три advisory. Прозаические строки к находкам — по-английски, как требует языковое правило проекта для публичных артефактов.

**ADV-RENDER-LIMIT-HIDES-HITS-IN-STANDALONE-COMMAND** — `render_leak_hits` in `src/agentmarshal/journal/capture.py:327` caps every rendering at `_RENDER_LIMIT = 20`, and `_run_leak_scan` in `src/agentmarshal/cli.py:1302` uses that same renderer; design.md justifies the cap by the merge transcript being "a document people read", which is an argument about the gate line, not about the command an operator runs precisely to learn *where* the leaks are. Past the twentieth hit that command now answers "and N more not shown" with no flag, no verbose mode and no private-API escape to see the rest, so the operator must fix twenty files and re-run to discover the twenty-first — a regression against the pre-change behaviour, where the category list was complete because it was bounded by the signature table.

**ADV-DIAGNOSTICS-FALLBACK-PRINTS-UNBOUNDED-STDERR** — `_keep_diagnostics` in `src/agentmarshal/journal/review.py:327` falls back, on `OSError`, to embedding the reviewer's entire decoded stderr in the note (`…they follow:\n{detail}`), which `_run_review` then prints (`src/agentmarshal/cli.py:729`) or `_with_diagnostics` folds into a `ReviewLaunchError` message; design.md's decision for this work says "The reviewer's error stream is kept, **not printed**. It can be long", and its best-effort clause allows the note to carry "either where the bytes were kept **or why they could not be**" — not the bytes themselves. The behaviour is arguable and the inline comment argues it, but acceptance criterion 1 requires the implementation to follow design.md's decisions *or record in design.md why it departed*, and design.md records the "sole occurrence" departure while leaving this one unrecorded.

**ADV-LAUNCHEDREVIEW-NOT-EXPORTED** — `launch_review` now returns the new `LaunchedReview` (`src/agentmarshal/journal/review.py:85`), but `src/agentmarshal/journal/__init__.py:40` still exports `SubmittedReview` and not `LaunchedReview`, even though `SubmittedReview` was on that list because it was `launch_review`'s return type; a package consumer that imports `launch_review` from `agentmarshal.journal` can no longer name the type it gets back.
