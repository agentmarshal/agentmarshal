Прошёлся по диффу, по контракту и по тому, что уже есть в репозитории (`steps.py`, `process_log.py`, `localstate.py`, ADR-0014 D9/D13, существующие status-тесты). Реализация в целом точно соответствует acceptance: `open_steps` — одна функция для обеих форм, лог читается один раз за запуск, пути идут на stderr, stdout-пины не сдвинулись, sidecar резолвится через `placement.project_root`, нечитаемый лог не валит команду.

Нашёл следующее.

**CR-162-001 (blocking).** Сценарий `stdout stays what the documentation promises` из требования «`status` prints the actual paths in use» (`openspec/specs/process-log/spec.md:430`) не назван в docstring ни одного теста. Всего в двух новых требованиях 22 сценария, а в `tests/test_status_steps.py` docstring'ами названы 21. Байт-точные пины, которые его фактически демонстрируют (`tests/test_status_view.py:81` и `tests/test_display.py:178`), в docstring называют совсем другие сценарии — про escaping, а не про stdout-контракт для парсеров. Acceptance 1 требует буквально «every scenario is demonstrated by a test whose docstring names it», так что это пропуск; лечится одной строкой docstring или крошечным тестом.

**CR-162-A02 (advisory).** `tests/test_status_steps.py:506` делает `state.log.chmod(0)` и затем ждёт на stderr `cannot read the process log`, но без защиты от запуска от root. Под root `iterdir()` на каталоге с режимом 0 проходит, `read_events` вернёт пустой список, сообщение не напечатается и ассерт упадёт. В репозитории уже есть ровно этот guard для такого же случая — `@pytest.mark.skipif(getattr(os, "geteuid", lambda: -1)() == 0, ...)` в `tests/test_outbox.py:479`; здесь он не поставлен. Первая половина теста (файл вместо каталога) от uid не зависит, так что достаточно вынести permission-ветку в отдельный тест с guard'ом.

**CR-162-A01 (advisory).** Docstring `format_overdue` (`src/agentmarshal/steps.py:479`) утверждает, что `90m`, `2h5m` и `1d3h` — «the units a deadline is given in», и то же говорят `design.md` и `tasks.md` 1.2 («the duration units `step start --deadline` already accepts — `1h30m`, `2h5m`, `1d3h4m7s`»). Фактически `_DURATION = re.compile(r"^(\d+)([smhd])$")` (`src/agentmarshal/steps.py:55`) через `fullmatch` принимает только один компонент, так что `--deadline 1h30m` падает со `StepError`. Оператор, скопировавший `past=2h5m` из вывода `status` в `--deadline`, получит отказ. Сам формат вывода контракту не противоречит — неверно именно обещание совместимости.

**CR-162-A03 (advisory).** `open_steps` (`src/agentmarshal/steps.py:436-445`) проходит весь список событий дважды на каждую задачу: сначала набор `step-ended`, потом цикл по `step-started`. Лог читается один раз за запуск (как и требует спека), но в форме списка стоимость — O(задачи × события). При текущем `DIRECTORY_CAP_BYTES = 50 MiB` (≈250k событий) и ~160 задачах в этом проекте это десятки миллионов словарных обращений поверх уже дорогого парсинга — `agentmarshal status` без аргументов станет заметно медленным. Группировка step-событий по `task` один раз за запуск убирает множитель.
