Прошёлся по диффу и по дереву репозитория, проверил spec/tasks/design, quickstart и код. Тесты запустить не дали (sandbox отклонил `pytest`), поэтому проверка кода статическая.

**dry-run-empty-snapshot-unreported** — `src/agentmarshal/journal/review.py:404-412`: комментарий обещает «the caller is told which of the two it got», но `dry_run_review` возвращает `None`, и `src/agentmarshal/cli.py:609` печатает одну и ту же строку «dry run: reviewer output has a parseable verdict; nothing was recorded» и когда snapshot распакован из `HEAD`, и когда его подменили на пустой каталог. В greenfield-репозитории (нет коммита) dry run сообщает об успехе, хотя ровно то свойство, ради которого design.md отступил от исходного решения — разрешение относительного пути внутри населённого snapshot, свойство №2 из proposal 015 — не было проверено вообще. Тест `test_dry_run_works_in_a_repository_with_no_commit` это и фиксирует: он ассертит тот же «parseable verdict». Это тот самый режим отказа, который задача объявляет своей целью устранить («an unstated boundary reads as a guarantee»; «a dry run must not be mistaken for evidence»).

**dry-run-git-failure-read-as-no-commit** — `src/agentmarshal/journal/review.py:407-410`: `except ReviewLaunchError` ловит всё, что может поднять `_run_git`, включая `cannot run git: <OSError>` (git не установлен) и `git rev-parse ... failed: not a git repository`. Все эти случаи молча трактуются как «пустое дерево», и dry run продолжается в пустом каталоге. Ветка должна различать «HEAD нет» и «git не отработал».

**model-guard-substring-match** — `src/agentmarshal/journal/review.py:395`: проверка `"{model}" in template` идёт по сырой строке env вместо только что написанного `_unsupported_placeholder`. `{model:>8}` или `{model!r}` подстроку не содержат — guard молчит, и `_reviewer_command(reviewer_model or "", ...)` подставляет пустую строку. Обратно: экранированное `{{model}}` (форматируется в литерал `{model}`, модель не нужна) подстроку содержит — dry run без `--model` падает с требованием `--model`.

**placeholder-error-echoes-whole-command** — `src/agentmarshal/journal/review.py:222-224`: отказ печатает в stderr полное значение `AGENTMARSHAL_REVIEWER_CMD`. Шаблон вендорского CLI нередко несёт `--api-key`/токен, и это единственное место, где инструмент выводит значение переменной дословно — в CI это уезжает в лог сборки. Сам по себе замысел (дать оператору что искать) верный, но стоит резать до элемента shlex или маскировать.

**dry-run-zero-sha-check-undocumented** — `src/agentmarshal/journal/review.py:430-435`: dry run дополнительно требует, чтобы `reviewed_commit` был равен 40 нулям. Ни quickstart, ни spec, ни design.md этого не называют, хотя acceptance требует «the implementation follows design.md's decisions or records in design.md why it departed» — записано только в комментарии к коду. Reviewer, который подставляет собственный SHA, получит отказ без объяснения в документации.

**contract-documents-path-dangles** — контракт объявляет `documents = ["openspec/changes/document-the-reviewer-contract/", ...]`, но в дереве есть только `openspec/changes/archive/2026-09-17-document-the-reviewer-contract/`. Путь, названный в самом prompt'е ревьюера как contract material, не резолвится. Отдельно: acceptance говорит про «the two documentation scenarios», а в spec.md documentation-сценарий один (пять сценариев всего, четыре из них закрыты тестами с именующими docstring'ами) — по существу критерий выполнен, но счёт расходится.

Остальное сходится: prompt у dry run и у recorded path строится из одного `_REVIEW_PROMPT` через `_review_prompt`, закреплённый 0.3.0-тест (`tests/test_review_launcher.py:1162`) не тронут, quickstart называет все четыре обязательных факта, `tasks.md` отмечен по фактически сделанному, отказ по placeholder'у называет токен и проверяется тестом, не ассертящим всё предложение.
