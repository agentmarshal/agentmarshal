Six advisory points, none of which contradict ADR-0001 or ADR-0005:

**dry-run-commit-check-unspecified** — `src/agentmarshal/journal/review.py:422` rejects any verdict whose `reviewed_commit` is not the all-zeros SHA. That gate appears in neither the spec requirement (which promises to "report whether its output yields a parseable verdict"), nor the quickstart's description of `--dry-run`, nor `design.md`'s decision list, which says the dry run "hands the output to the same verdict parser the real path uses" and stops there. It is also the one dry-run branch with no test. A reviewer that echoes the commit it actually observes in the snapshot fails a dry run for a reason the documentation does not predict. The behavior is defensible — it mirrors `launch_review`'s own mismatch check — but it is an undeclared addition and should be recorded in `design.md` and covered.

**unclosed-brace-refusal-unsearchable** — `src/agentmarshal/journal/review.py:223`. Proposal 015's third measured failure was a value that "had lost a closing brace to a shell quoting accident, and the message gave nothing to search for." That exact input still lands here: `string.Formatter().parse("{model")` raises `ValueError`, and the refusal is the unchanged `"AGENTMARSHAL_REVIEWER_CMD has an invalid placeholder"` — carrying neither the offending argument nor the formatter's own diagnostic. The comment above it accepts this because there is no field name, but the argument text and the `ValueError` message are both available and are what an operator would grep for. This fallback path has no test.

**placeholder-test-partly-vacuous** — `tests/test_review_launcher.py:316`. The `"unsupported"` parametrization asserts `"unsupported" in str(raised.value)`, which the fixed phrase "unsupported placeholder" satisfies whether or not the token is interpolated. Only the `"0"` case actually constrains the behavior; the first case would survive deleting the `: {named}` suffix.

**dry-run-ignores-remaining-flags** — `src/agentmarshal/cli.py:581`. `--dry-run` refuses `--task` and `--commit` but silently ignores `--base`, `--role`, `--vendor`, `--email`, and `--reviewed-finding`. An operator adding `--dry-run` to a full recorded-review invocation is told two flags do not apply while five others are dropped without comment.

**dry-run-needs-a-commit-in-practice** — `src/agentmarshal/journal/review.py:403`. The dry run archives `HEAD`, so in a repository with no commits — a plausible state right after `agentmarshal init`, which is the point in the quickstart where an operator would first want to exercise their command — it fails with the raw `git archive failed: fatal: not a valid object name: HEAD`. The spec scenario and the quickstart both imply no commit is needed. `design.md` records the `HEAD` departure but asserts "it still needs neither task nor commit", which holds only once HEAD resolves. Worth either a clearer refusal or a sentence in the quickstart.

**preserve-output-flag-is-dead-weight** — `src/agentmarshal/journal/review.py:281`, `:295`, `:408`. The `preserve_output` keyword threaded through `_reject` and `_parse_verdict` has exactly one non-default caller, and that caller immediately calls `_preserve_output` itself; the only net difference from the default path is the wording of the suffix. Wrapping the plain `_parse_verdict(output)` error would drop the parameter from two shared functions.

**spec-has-one-documentation-scenario** — `openspec/specs/reviewer-adapter/spec.md`. The contract's first acceptance criterion excepts "the two documentation scenarios", but the delivered requirement ships a single scenario covering both obligations that `tasks.md` splits into 1.1 and 1.2. The substance is all present; the count a verifier is told to expect is not.
