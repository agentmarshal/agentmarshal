**null-value-silently-defaulted** — `src/agentmarshal/settings.py:81-83`, `114-116`, `128-130` и `_section` на `68-70` считают отсутствием не только отсутствующий ключ, но и присутствующий JSON `null`: `section.get(...)` возвращает `None` и для `{"review": {"changes_required_threshold": null}}`, и для `{"contract": {"require_agreement": null}}`, и для `{"review": null}`. Значение в файле есть, оно не integer ≥ 1 / не boolean / не object — то есть ровно «present but malformed», — но reader молча возвращает default, а `doctor` печатает `OK: project setting contract.require_agreement: False`. Это противоречит acceptance-критерию «a present but malformed value is never silently replaced by the default» и требованию спеки «A key that is present SHALL be validated»; в design.md случай `null` не разобран, departure не записан. Соседние ридеры того же `project.json` в `src/agentmarshal/journal/capture.py:217,226,239` и `capture.py:694` используют `section.get(key, default)` с последующей проверкой типа, поэтому явный `null` у них падает — новый модуль слабее принятой в репозитории конвенции именно в том месте, ради которого он написан.

**design-claims-value-never-printed** (advisory) — `openspec/changes/archive/2026-10-03-project-settings-0-5-0/design.md:46-48` утверждает «The malformed value itself is never printed — a string carrying a control character would forge output if echoed», но `src/agentmarshal/settings.py:93-100` подставляет значение в сообщение дважды (`entry {entry!r} is not a non-empty string`, `repeats entry {entry!r}`), и оно уходит в вывод `doctor`. Фактической дырки нет: `!r` экранирует и Cc, и bidi-символы, так что подделать строку вывода нельзя — но защищает здесь repr, а не заявленное в design умолчание, и записанное решение расходится с кодом.

**unknown-section-keys-silently-ignored** (advisory) — `src/agentmarshal/settings.py:79-135` читает только три известных имени и ничего не говорит о прочих ключах в секциях `review`/`contract`, тогда как `capture.py:212-216` и `capture.py:689-693` для своих секций явно отказывают на «unsupported fields».
